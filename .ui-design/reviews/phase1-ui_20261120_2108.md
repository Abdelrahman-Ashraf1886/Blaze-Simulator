# Design Review: Phase 1 UI (shell, dashboard, projects)

**Review ID:** phase1-ui_20261120_2108
**Reviewed:** 2026-11-20 21:08
**Target:** `src/app/AppShell.tsx`, `src/features/dashboard/*`, `src/features/projects/*`, `src/components/**`, `src/styles/globals.css`
**Focus:** Comprehensive (visual, usability, code, performance) · Context: engineering data display · Platform: desktop (Electron, 1100×700 min window up to 4K)

## Summary

The shell reads as an engineering tool: neutral dark surfaces, one accent, monospaced
tabular numbers, honest phase labels on unbuilt sections. Window-size testing at
1100 px and 2560 px exposed layout problems in the data tables and an unbounded
content width. A production build check found the renderer bundle unminified.
All major and minor issues below were **fixed in this review** and re-verified with
screenshots plus the full unit and e2e suites.

**Issues Found:** 9 — Critical 0 · Major 3 (fixed) · Minor 3 (fixed) · Suggestions 3 (open; scheduled)

## Major Issues

### 1. Table cells wrap at the minimum window width (fixed)
**Location:** `DashboardPage.tsx`, `ProjectsPage.tsx` · **Category:** Visual
At 1100 px, frame labels and timestamps broke onto two lines and rows doubled in height,
which hurts scanning. **Fix:** `whitespace-nowrap` on all cells. The name column takes the
remaining width with `w-full max-w-0 truncate`, and the full name is available as a `title` tooltip.

### 2. Unbounded content width on large monitors (fixed)
**Location:** pages, `page-header.tsx` · **Category:** Visual
At 2560 px the name column spanned ~1100 px and rows were hard to track across the screen.
**Fix:** page header and body are capped at `max-w-[1760px]` and centred. The status column widens to 340 px.
Exception: 3D viewports must **not** be capped (see suggestion 1).

### 3. Renderer shipped unminified with zod (fixed)
**Location:** `electron.vite.config.ts`, `electron/ipc/contract.ts` · **Category:** Performance
The bundle was 1,091 kB because electron-vite does not minify the renderer by default,
and zod was pulled in through the shared contract. **Fix:** set `minify: true`. The contract is
now types and constants only, and the zod schemas moved to `electron/ipc/schemas.ts`
(main only), with a compile-time assertion that schema and type agree. **Result: 351 kB.**

## Minor Issues

### 4. Low-contrast tertiary text (fixed)
`--color-fg-subtle` was L=0.54 on L=0.155, borderline for 11–12 px text. It is now L=0.61.
This affects empty states, table headers and metadata.

### 5. Verbose locale timestamps (fixed)
"Nov 20, 2026, 09:04 PM" was wide and not sortable at a glance. It is now `2026-11-20 21:04`
in tabular mono.

### 6. Header actions detached from content on wide screens (fixed)
Covered by the header width cap in issue 2.

## Suggestions (open)

### S1. Responsive 3D viewports (Phase 2 requirement)
No 3D exists yet. The Phase 2 acceptance criteria now require each of the following:
- The `<Canvas>` fills a flex/grid cell (`min-h-0 min-w-0`) and resizes with it. R3F uses a
  ResizeObserver, so viewports follow window **and** panel resizes, with no fixed pixel sizes.
- `dpr={[1, 2]}` plus drei `<PerformanceMonitor>` / `<AdaptiveDpr>` to drop resolution
  under load on 4K or high-DPI displays. Workshop uses `frameloop="demand"`.
- The perspective camera keeps a constant vertical FOV. The orthographic camera zoom is
  derived from the bounding box and aspect, so the drone stays framed after resize.
  Fit-to-view runs on resize.
- Panels are resizable (side panels collapsible, minimum viewport size enforced), and the
  layout is persisted per user.
- Labels and connection-point markers are rendered at a constant screen size.
- Test: Playwright resizes the window to 1100×700, 1920×1080 and 3840×2160 and asserts the
  canvas matches its container and the model stays in frame. Frame-time is logged at 4K.

### S2. Route-level code splitting
Use `React.lazy` per feature once three.js lands, so the dashboard does not load the 3D stack.

### S3. Dialog motion
Add a subtle 120 ms fade/scale on dialogs (respecting `prefers-reduced-motion`) to meet
the "subtle animations" direction.

## Positive Observations
- Single accent; status colours reserved for state; numbers in tabular mono.
- Disabled roadmap sections are clearly labelled (`P2`…`P8`) and non-interactive, with no placeholder screens.
- Global `:focus-visible` ring. Row actions appear on hover **and** keyboard focus (`focus-within`).
- Every list has empty and error states. The create dialog validates and shows server errors.
- Stores are factory-built and unit tested with a fake API.
