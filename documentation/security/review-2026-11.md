# Milestone 8.11 security review — 2026-11-27

Source review of the Electron 45.4.1 desktop app (`package-lock.json:4361–4364`). The likelihood ratings assume one desktop user opening files they choose. The phase plan calls for private, unsigned Windows distribution with checksums and no automatic updates (`documentation/plans/phase-8-quality.md:52–59,65`). Milestone 8.11 records findings, follows packaging in 8.6, and relies on 8.5 for packaged and hostile-file regression coverage. The acceptance plan includes truncated, oversized, deeply nested and wrong-type files with stated time and memory limits. Performance limits remain a decision under D15. The plan also calls out backup coverage and the unsigned-installer warning (`documentation/plans/phase-8-quality.md:66,78–85,90–109,117–125`).

| **Medium** | `electron/main/assets/store.ts:16–31,64–70`, `electron/main/assets/gltf.ts:84–90,196–236` | Model inspection runs synchronously in main before worker dispatch. | **Medium** | `electron/main/assets/hull.ts:68–107,115–145,174–177`, `electron/main/assets/hull-async.ts:14,91–96,125–146,158–164` | The hull worker allocates vertices from the declared accessor count before checking buffer bounds and appends transformed vertices without a total input budget. Hull output and containment caps apply later. A selected model can consume CPU or memory and potentially terminate the app through process-wide memory pressure. The pool bounds threads and has an idle timeout, but queued jobs and active job time are uncapped. | Check integer counts, offsets, strides and dense/sparse spans before allocation. | **Medium** | `electron/main/assets/terrain-store.ts:27–50,62–76`, `src/domain/terrain.ts:25–43,53–59,82–89` | Import synchronously reads, decodes and tokenizes the whole selected ASC before checking the grid dimensions or sample count. | **Low** | `electron/main/assets/store.ts:16–27`, `electron/main/index.ts:337–352`, `electron/main/components/pack.ts:22–23,50–83,88–96`, `electron/main/gpu-preference.ts:22–36` | Models and packs stat a path before reading it again. JSON has no explicit document-depth policy. Packs also coerce unvalidated names into diagnostic text, so a malformed name can throw before the field validator reports it. A pack or model needs a changing file for the read race, while an oversized preference file requires access to app data and can stall startup. | Open once and perform a regular-file bounded read on the same handle. Apply a small schema-derived preference cap, explicit JSON nesting/work budgets where needed, and format diagnostic names only when they are strings. |
| **Low** | `electron/main/index.ts:42–44,275–281`, `electron/main/assets/store.ts:80–94,119–125` | The asset URL checks the host and digest-shaped path, then serves a matching filesystem entry with wildcard CORS. An outside-file read or oversized stored-file read would additionally require a link or other modification in the asset store. Ordinary import writes bytes by digest. These preconditions make the exposure low for normal file picking. | Restrict access to the app's rendering session, remove wildcard CORS if the renderer can still load models, and serve only registered, bounded regular files with link-safe containment. Reuse the bounded read for hull backfill. |
| **Low** | `electron/main/telemetry/format.ts:24–64`, `electron/main/telemetry/reader.ts:43–55,70–114,125–146,222–228,298–307`, `electron/main/telemetry/store.ts:43–52,82–90,95–124` | The recording reader checks frame lengths against remaining file bytes and verifies CRCs, then allocates whole header/end/request payloads and accumulates request lines and frame indexes. The UUID/run checks and app-store-only access make this unlikely today. No file-picker entry point for arbitrary BLZR files was found. | Reject oversized frames before CRC processing or allocation, bound index growth and metadata/channel sizes, and stream replay requests with cancellation. Derive reader ceilings from the current writer and supported recording sizes (`electron/main/telemetry/writer.ts:104–124`). |
| **Low** | `electron/main/telemetry/verify.ts:48–57,85–108,119–146`, `simulation-engine/engine-host/src/protocol.rs:451–458` | Replay checks the command kind and ID, then sends the original JSON to the sidecar without applying the normal main-side command schemas. An app-store modification plus verification is required. | Validate each recorded request with its matching wire schema and size/work bounds before replay. ## Controls and verification limits

- **Electron boundary.** The sole app `BrowserWindow` sets `sandbox: true`, `contextIsolation: true`, `nodeIntegration: false` and `webSecurity: true`. No other production window or webview enablement was found. The preload exposes named APIs and strips IPC event objects from callbacks. Packaged main-frame navigation is denied, and the window is loaded from the bundled renderer. The CSP header code uses packaged `script-src 'self'`, blocks plugins and base URIs, and allows the custom scheme, blob and data for asset handling. Development adds inline scripts and localhost connections. No explicit permission-handler or frame-source rule was found. Confirm effective CSP on the packaged `file:` document and any permission policy in 8.5 (`electron/main/index.ts:78–96,117–148`, `electron/preload/index.ts:4–94`, `node_modules/electron/electron.d.ts:20573–20581`).
- **File boundaries.** No direct renderer-controlled arbitrary read or write path was found. The dialog paths and ID-derived storage paths are distinct from renderer-proposed display names. Terrain checks stored digests, and recordings resolve UUID-based file names through the run repository. glTF checks core buffer/image URIs for embedded data and GLB container lengths. No user-facing ZIP extraction or project-archive importer was found on these routes, so there is no ZIP-bomb test target in the current app. Decoded data and geometry expansion still need budgets. PDF checks the current report route before and after printing, and HTML-escapes the footer title. The notices opener constructs a fixed TXT path with no renderer input, and GPU switches come from the parsed enum (`electron/main/index.ts:193–201,275–370,399–413`, `electron/main/assets/gltf.ts:96–116,129–153`, `electron/main/assets/terrain-store.ts:62–76`, `electron/main/telemetry/store.ts:43–52`, `electron/main/telemetry/report-pdf.ts:8–46`, `electron/main/notices.ts:3–5`, `electron/main/gpu-preference.ts:8–27`, `electron/ipc/schemas.ts:24–29`).
- **Fuse readback and ship list.** Read-only inspection of the local stock `node_modules/electron/dist/electron.exe` returned fuse wire v1. The three Node fuses above were enabled and the two ASAR enforcement fuses were disabled. The mapping and byte states come from `node_modules/@electron/fuses/dist/config.js:13–18` and `node_modules/@electron/fuses/dist/constants.js:4–8`. Builder skips flipping without `electronFuses`, defaults to ASAR, and can embed ASAR hash metadata independently (`node_modules/app-builder-lib/out/platformPackager.js:227–236,261–267,445–459`, `node_modules/app-builder-lib/out/electron/ElectronFramework.js:51–53`). The configured payload includes `out/**` and `package.json`, excludes maps, unpacks `better-sqlite3`, and adds the engine and notices as resources for NSIS and portable Windows x64. No release executable was available for final fuse readback or shipped-file enumeration (`electron-builder.yml:4–24`).
- **Offline dependency review.** npm and Cargo lockfiles provide exact resolution inventories. The generated notices also list bundled Electron, Node, Chromium and SQLite versions (`package-lock.json:3417–3420,4361–4382,7699–7704,8490–8493`, `simulation-engine/Cargo.lock:1–12`, `build/notices/THIRD-PARTY-NOTICES.txt:3045,14457–14465,14669`). No usable cached npm advisory response or local RustSec advisory checkout was found in the inspected cache locations, and `cargo-audit` was unavailable. No vulnerability match was established. Registry audit, current RustSec matching and advisory matching for Electron's embedded components remain unverified. No package install, audit command, app launch, build, or test was run.

## Prioritized fixes

1. Bound model and terrain work before allocation. Move model inspection and terrain parsing off main and make hull work cancellable.
2. Complete 8.6 packaging hardening. Set and verify the five fuses, gate test and debugging options, and inspect the final NSIS and portable payloads.
3. Guard all IPC senders and cap expensive requests, responses and concurrency. Bound both NDJSON paths and validate sidecar replies and recording replay inputs.
4. Add the 8.5 hostile-file fixtures for parser limits and export behavior. Fix CSV header neutralization and final save-path confirmation alongside those regressions. Match the release dependency inventory against advisory data when available.
